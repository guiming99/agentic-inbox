# Agentic Inbox v1.0.5 Plan

## Purpose

v1.0.5 is the next engineering iteration after the v1.0.4 production observation period. It is intentionally based on the v1.0.4 release candidate and must not modify `main` or the current production deployment.

CloudMail is used only as a technical reference. No CloudMail code is copied or merged.

## Scope

### 1. Full Email Boundary

Establish and audit the rule that Reply, Reply All, and Forward operations must receive a complete email detail object, never an incomplete list/summary object.

Agentic Inbox already uses React Query for list/detail/thread data, so v1.0.5 should preserve that architecture rather than introducing a second `detailMap` state model.

Audit targets include every compose entry point, thread message action, draft reply path, and refresh/cache path.

### 2. List/Detail performance

Audit the mailbox list API to determine whether full HTML bodies, large fields, or attachment metadata are unnecessarily returned in list responses.

If a measurable payload/query problem exists, introduce a lightweight list representation while keeping full detail retrieval separate. Do not change the storage model merely to imitate CloudMail.

### 3. Webhook foundation

Design a mailbox-level webhook for downstream automation/agent integrations:

- configurable endpoint
- optional secret authentication
- bounded retry behavior
- non-blocking delivery
- failure logging without breaking mail receipt
- stable JSON event payload

Webhook delivery must be downstream of successful email persistence so webhook failures cannot break inbound mail storage.

### 4. Retention / cleanup foundation

Evaluate automatic cleanup of old mail and associated R2 attachments as a separate lifecycle operation.

Deletion must preserve the existing mailbox semantics and remove attachment objects only when their owning email is actually deleted. No cleanup will be enabled by default until the lifecycle is verified.

## Explicit non-goals

- Do not merge CloudMail branches or commits.
- Do not change `main`.
- Do not alter the v1.0.4 production baseline.
- Do not replace Agentic Inbox's React Query architecture with Pinia-style state.
- Do not rewrite the existing HTML/CID rendering and security model.
- Do not regress RFC-based threading toward subject-based matching.

## Validation gate

Before any v1.0.5 implementation is merged:

1. Verify v1.0.4 production behavior remains stable.
2. Review the complete diff against `release/1.0.4`.
3. Run/build-test all affected Worker and frontend paths.
4. Verify receiving, sending, Reply, Reply All, CC, Forward, multi-recipient Forward, threading, Telegram/archive behavior, and attachment rendering.
5. Only then consider individual v1.0.5 features for implementation and eventual merge.
